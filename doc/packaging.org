#+TITLE: Packaging options and closure sizes

This document is for users who configure this flake. The package source is the authority for option behaviour.

* xc-cli

=xc-cli= defaults to no compilers. Set =compilers= to a list of compiler packages. The unversioned attributes (=xc8=, =xc16=, =xc32= and =xc-dsc=) select the latest packaged version. Versioned attributes, such as =xc16_1_61=, keep a firmware build on a specified compiler version. The first selected compiler of each family provides the unversioned command wrappers, such as =xc16-gcc=. Use =xc-run= to run another selected compiler by its full path.

=packs= defaults to =null=. With selected compilers, this installs the device packs from their installer MCU options and =othermcu=: =xc8= selects =8bitmcu=; =xc16= and =xc-dsc= select =16bitmcu=; and =xc32= selects =32bitmcu=. The flake runs the installer once for each selected MCU-option combination. Set =packs= to a list to use exactly those packs. Set =packs = [ ]= to install no packs.

=withMplabProjects= defaults to =false=. Set it to =true= to add the command-line MPLAB-X subset and =mplab-gen=. =ideVersion= defaults to =mplab-x-unwrapped.version= and sets the MPLAB-X path used by the environment.

#+BEGIN_SRC nix
pkgs.xc-cli.override {
  compilers = with pkgs; [ xc16_1_61 xc16_2_10 ];
}
#+END_SRC

* mplab-x

=mplab-x= takes =xc-cli=. It defaults to =xc-cli= with no compiler. Pass a configured =xc-cli= when the IDE must use compiler commands.

=toolPacks= defaults to =null= and installs all bundled tool packs. Set it to a list of bundled tool-pack names, such as =[ "PICkit5_TP" ]=, to select those names. Set =toolPacks = [ ]= to install no tool pack.

=packs= defaults to =[ ]=. It adds extra packs to the packs from =xc-cli= and =toolPacks=. Use it for a pack from =fetchMplabPack=, including a newer device or tool pack.

The package provides =mplab_ipe= for the IPE GUI and =ipecmd= for the IPE command line. It also provides =mplab-x-run=, =mplab-make= and =mplab-gen=.

* mplab-x-unwrapped pack outputs

=mplab-x-unwrapped.devicePacks { mcuOptions }= builds device packs and =arm/CMSIS= for the specified installer MCU options. The valid values are =8bitmcu=, =16bitmcu=, =32bitmcu= and =othermcu=. =mplab-x-unwrapped.toolPacks= contains the bundled tool packs. =mplab-x-unwrapped.packs= contains all bundled packs. =mplab-x-unwrapped.installerHelp= contains the installer help and version output. =mplab-x-unwrapped.commandLineSubset= contains the command-line MPLAB-X files used by =withMplabProjects=.

The measurements below are from MPLAB-X 6.35 on 2026-10-23. Each device-pack row includes =othermcu= and =arm/CMSIS=. The DFP count does not include =arm/CMSIS=. The installer also installs 15 tool packs on every run; =toolPacks= keeps those 15 packs and is 2.69 GiB.

| MCU options            | DFPs | Directories | Size (GiB) |
|------------------------+------+-------------+------------|
| =8bitmcu=, =othermcu=  |   27 |          28 |       2.72 |
| =16bitmcu=, =othermcu= |   24 |          25 |       2.84 |
| =32bitmcu=, =othermcu= |   84 |          85 |       4.87 |

* Device-pack compiler option

A compiler does not search the packs folder. Pass =-mdfp=/opt/microchip/mplabx/v<version>/packs/<vendor>/<name>/<version>/<compiler-dir>=, for example the =xc16= directory for both XC16 and XC-DSC. MPLAB-generated makefiles pass this option from =DFP_DIR=.

* fetchMplabPack

=fetchMplabPack= fetches one pack. Set =name=, =version= and =hash=; =vendor= defaults to ="Microchip"=. It removes the archive manifest so its output matches a pack installed by MPLAB-X.

#+BEGIN_SRC nix
pkgs.fetchMplabPack {
  name = "dsPIC33E-GM-GP-MC-GU-MU_DFP";
  version = "1.7.401";
  hash = "sha256-NSLRbSv/UQcvVhFLhqc+eQixQupAA5aFuCwdoHyVEyc=";
}
#+END_SRC

To get a hash, set =hash = lib.fakeHash;=, build the expression and copy the hash from the error. For an installed bundled pack, run =nix hash path= on its =<vendor>/<name>/<version>= directory. =fetchMplabPack= is in =legacyPackages= and in the overlay, not in =packages=.

* Checkout tasks

Run these tasks from a checkout with =nix develop=. The development shell provides Babashka.

#+BEGIN_SRC sh
nix develop -c bb installer-help
nix develop -c bb packs [--online] [filter]
nix develop -c bb project-config <project-directory-or-configurations.xml>
nix develop -c bb ci-image --help
nix develop -c bb package --help
nix develop -c bb test
#+END_SRC

=installer-help= prints the packaged installer help and version. =packs= lists bundled packs by default, or the Microchip online index with =--online=; the optional filter selects pack names. =project-config= reads an MPLAB project directory or its =nbproject/configurations.xml= and prints an =xc-cli.override= block with its versioned compiler and pinned packs. =ci-image= builds a project-specific image stream; see [[file:../examples/mplab/README.org][the CI example]]. =test= runs the offline checkout-task tests.

The printed block requires a =pkgs= binding that includes this flake's packages. In a downstream flake, add =microchip.overlays.default= to the package set's =overlays= list, as in the README example, then use the block where that =pkgs= is in scope. To use this flake directly, with its input named =microchip=, use this scope:

#+BEGIN_SRC nix
let
  pkgs = microchip.legacyPackages.x86_64-linux;
in
# Paste the project-config output here.
#+END_SRC

* Compiler package scaffolding

=bb package= adds versions of the existing =xc8=, =xc16=, =xc32= and =xc-dsc= families for =x86_64-linux=. Run it from the checkout root. With no =--write=, it downloads the original installer, computes its raw-file SRI hash and prints a candidate version file and =pkgs/default.nix= registration. It realises only the installer's =fetchurl= source, not the compiler installation.

#+BEGIN_SRC sh
bb package --url \
  'https://ww1.microchip.com/downloads/en/DeviceDoc/xc16-v1.61-full-install-linux64-installer.run'
#+END_SRC

Known installer filenames supply the family and version. Supply =--family= and =--version= for a versionless/ambiguous Linux filename; if the filename already identifies either value, the explicit value must agree. Alternatively, omit =--url= and use =--family xc16 --version 1.61= to use the shared builder's canonical download locations. Only numeric dotted versions and HTTPS URLs without embedded credentials, query strings or fragments are accepted. Windows, macOS and ARM installers are not supported. XC16 before 1.50 requires the Linux =.run.tar= layout; the other supported layouts use =.run=.

Use a trusted vendor download link. A filename and a freshly calculated hash do not establish provenance or show that an installer works. The hash pins the downloaded bytes, before unpacking. The optional =url= argument in each family's =common.nix= selects a download source; archive handling and installer/licence flags still depend on the family and version. An unsupported layout requires review of that shared code, not a guessed flag change.

** Verification and writing

Add =--verify= to build a temporary candidate in =xc-cli=, check its reported family/version, compile and link a small program at =-O3=, scan for the known Free-mode diagnostics and require a non-empty ELF file. Existing releases can be previewed and verified without replacing them:

#+BEGIN_SRC sh
bb package --family xc16 --version 1.61 --verify
bb package --family xc-dsc --version 4.00 --verify
#+END_SRC

The verification profiles are in =bb/package_verify.nix=:

- XC16 :: dsPIC33EP512MU810, with built-in device support.
- XC8 :: PIC18F47K40 with PIC18F-K_DFP 1.17.312.
- XC32 :: PIC32MX795F512L with PIC32MX_DFP 1.7.380.
- XC-DSC :: dsPIC33CK64MP105 with dsPIC33CK-MP_DFP 1.16.521.

These are smoke tests, not tests of every device or optimisation. Older or future releases can need another profile. The banner check permits extra zero-only components (XC-DSC 4.00 reports =v4.00.00=), but rejects a different non-zero patch version. A failed install, version check, compile, link or licence check stops the command; it does not rewrite shared packaging logic to force a pass.

Verification needs unprivileged user namespaces. Check free disk space first: compiler installations can use several GB. Temporary candidate files are kept under the checkout's =.tmp/= and removed on success or failure. The task does not run garbage collection.

For a new version, review the dry-run output, then rerun the same selection with =--verify --write=. For example, replace =VERSION= with the actual new release:

#+BEGIN_SRC sh
bb package --family xc16 --version VERSION --verify --write
#+END_SRC

The command writes =pkgs/<family>/<version>.nix= and adds its versioned attribute to =pkgs/default.nix=. The flake and overlay export that attribute automatically. It refuses an existing version file or registration, and aborts if the registry file has an editor lock or changed during preparation. Verification runs before either source file is written. =--write= without =--verify= is allowed, but the result is explicitly reported as unverified.

Default aliases, the README package table, =flake.lock=, staging and commits remain manual. Stage the new version file before evaluating it as a Git flake, because untracked files are excluded from that source. The command prints the required paths for =git add=; after staging, run =nix flake check --no-build= and review the diff. No compiler ELF file is patched or fixed up.

* Closure sizes

These closure-size measurements use =nix path-info -S= on realised paths on 2026-10-23, with MPLAB-X 6.35. Values are GiB, where 1 GiB is 1,073,741,824 bytes.

| Selection                                                    | Closure (GiB) | Closure (bytes) |
|--------------------------------------------------------------+---------------+-----------------|
| =xc-cli= with =xc8= and default device packs                 |          3.53 | 3,786,544,224   |
| =xc-cli= with =xc16= and default device packs                |          5.06 | 5,435,906,832   |
| =xc-cli= with =xc32= and default device packs                |         13.93 | 14,955,809,008  |
| =xc-cli= with =xc-dsc= and default device packs              |          4.11 | 4,415,098,128   |
| =xc-cli= with =xc16= and dsPIC33E-GM-GP-MC-GU-MU_DFP 1.7.401 |          2.50 | 2,683,095,400   |
| =xc-cli= with no compiler                                    |          0.36 | 386,383,872     |
| Default =mplab-x=                                            |          6.14 | 6,596,188,896   |

The bundled packs contain approximately 2.5 GB of duplicate files, most of them in the debugger tool packs (measured with =jdupes=, 2026-10-21). Nix does not de-duplicate store files by default. =nix store optimise=, or =nix.settings.auto-optimise-store = true;= on NixOS, replaces duplicate files with hard links. This does not make a download from a binary cache smaller.

* Intent
A local build of `mplab-x`, `xc-cli` or `mplab-x-unwrapped` does not build or store the 14 GB of bundled packs. The bundled packs stay available as `mplab-x-unwrapped.packs` for users who select them.

* Summary
*Level:* production · *Tests:* smoke · *Docs:* README

** Scope
*** In scope
- `mplab-x-unwrapped` with one output, built with the installer's MCU exclusion flags; the leftover packs are removed before the copy to `$out`.
- A separate single-output derivation for the bundled packs (full installer), exposed as `mplab-x-unwrapped.packs` through `passthru`.
- README.org `** Device packs` and AGENTS.md `## Disk space` (sizes, GC roots).
*** Out of scope
- Extraction of the installer payload without the installer (no working extractor found).
- Convenience pack sets (task aebb7421).
- A newer MPLAB-X version.

** Acceptance
*** Core functionality
- [ ] The build-input graphs (`nix-store -q --requisites` of the `.drv`) of default `mplab-x`, default `xc-cli`, `xc-cli` with `withMplabProjects = true` and `mplab-x-unwrapped` do not contain the packs derivation (positive control: each contains its own derivation).
- [ ] `mplab-x-unwrapped.packs` builds, and its content is identical to the previous `packs` output (NAR hash).
- [ ] The `mplab-x-unwrapped` file list (`find -printf '%P %l %m\n'`) is identical to the previous `out`; a content difference is limited to `Uninstall_MPLAB_X_IDE_v6.dat`.
- [ ] `commandLineSubset`: its 355 files are byte-identical to the previous ones.
- [ ] In `mplab-x`, `mplab-gen` writes `.mk` files with no `/nix/store` line and the selected DFP in `DFP_DIR`.
- [ ] Regression, basic level (AGENTS.md): `xc16_1_61` (with `xclm -status` `Mode: PRO`) and `xc-dsc_4_00` compile and link in `xc-cli` and in `mplab-x`.
- [ ] README.org and AGENTS.md describe the separate derivation and the new sizes.
*** Anti-criteria
- [ ] Must not: change the public attribute names, default versions, default pack selection or `flake.lock`.
- [ ] Must not: patch payload executables or jars.

** Decisions
- Separate derivations, with the MCU exclusions for the IDE build (parent decision while the user was away, 2026-10-22; to be confirmed) :: Nix builds every output of a derivation, so a `packs` output costs 14 GB on every local build. The installer has no all-packs switch, but `--8bitmcu 0 --16bitmcu 0 --32bitmcu 0 --othermcu 0` reduced the build-directory peak from 18.1 GB to 7.1 GB and the build time from 204 s to 133 s; the leftover packs (16 directories, e.g. tool packs) are deleted.
  Rejected:
  - Drop the packs output: removes the documented `mplab-x-unwrapped.packs`.
  - Extract the payload: the BitRock `.run` has no known extractor (`7z l` cannot open it).
  - One full installation shared by both derivations: it would store the 14 GB again.

** Risks
- A build that selects both derivations runs the installer twice.
- The installer flags can change in a new MPLAB-X version; recheck them on upgrade.
- `Uninstall_MPLAB_X_IDE_v6.dat` differs between installer runs, so the `mplab-x-unwrapped` store path changes once.

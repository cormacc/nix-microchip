* Intent
A project selects the device and tool packs that it needs, pinned independently of the MPLAB-X version, so that an IDE closure can omit the 14 GB of bundled packs and the compiler-only environment (task bf4262f4) can supply the DFP that every generated compile passes with -mdfp.

* Summary
*Level:* production · *Tests:* smoke · *Docs:* README

** Scope
*** In scope
- `fetchMplabPack`: one pinned pack from https://packs.download.microchip.com/, exported in the overlay and `legacyPackages`.
- `mplab-x-unwrapped`: the bundled packs move to a separate `packs` output.
- `mplab-x`: a `packs` argument that assembles the packs folder in the root filesystem. The default is the bundled packs.
- README.org: pack selection, the hash procedure, and the store de-duplication option.
*** Out of scope
- The compiler-only environment (task bf4262f4) and IDE-free MPLAB makefile builds (task b0aa04ab).
- A registry of pinned packs in this flake. Projects pin their own packs.
- Stable paths for PATH_TO_IDE_BIN, MP_JAVA_PATH and the hexmate step in generated makefiles (task b0aa04ab). DFP_DIR became stable as a side effect.
- A smaller default pack selection.

** Decisions
- Multiple outputs for the bundled packs :: the installer output stays the same, needs no extra downloads, and the default pack set is unchanged.
  Rejected:
  - Fetch every bundled pack with `fetchMplabPack` and remove packs from the installer output: 147 downloads for the default IDE, and a pin list to regenerate for each IDE version.
- The root filesystem builds the packs folder from real directories with symlinks to the files (`cp -rs`) :: packslib finds packs with `Files.walkFileTree` without `FOLLOW_LINKS` and a depth of 4 (`com.microchip.packslib.packutilities.FileLocator.getAllTypeFiles`), so it does not find a pack whose directory is a symlink.
  Rejected:
  - One symlink for each <vendor>/<name>/<version>: measured, `prjMakefilesGenerator.sh` reported "There are no DFPs in the local pack repositories".
  - Bind mounts: each mount costs each compile an xclm search.
- A wrapper at /opt/microchip/mplabx/v<version>/sys/java/*/bin/java sets `-Dpackslib.packsfolder=/opt/microchip/mplabx/v<version>/packs` (read by `com.microchip.packslib.parsers.ConfigParser.getSystemRepoLocation`) :: without the property, packslib derives the folder from its jar's real location, the store path of the installation, and the walk does not follow the packs symlink there. The IDE launcher (`jdkhome` in `mplab_ide.conf`) and the CLI scripts (`jdk_java` in `common-vars.sh`) start java from the /opt path.
  Rejected:
  - `-J-Dpackslib.packsfolder` in the `mplab_ide` wrapper: only the IDE launcher takes -J options.
  - `JAVA_TOOL_OPTIONS` in mplab-x-run: every JVM prints a "Picked up JAVA_TOOL_OPTIONS" line.
- The installation keeps packs as a symlink to the assembled folder :: a file path below the installation's packs directory still resolves inside the environment. A packslib walk from that path finds nothing, because its start is a symlink.
- `fetchMplabPack` output is the pack root, without the archive's package.content manifest :: its hash is then the `nix hash path` of an installed copy, and a derivation can use `${pack}/xc16` directly.

** Shipped
- `fetchMplabPack` (`pkgs/fetch-mplab-pack/default.nix`), in the overlay and `legacyPackages`; `packages` contains only derivations.
- `mplab-x-unwrapped.packs`: the 147 bundled packs. The `out` closure is 1.97 GB (16.0 GB before).
- `mplab-x` `packs` argument. The default closure grows by 22 MB (the symlinks of the packs folder): 19.66 GB.
- Makefiles that MPLAB-X tools generate set DFP_DIR to /opt/microchip/mplabx/v<version>/packs/<vendor>/<name>/<version>, not to a store path.
- ADDED README.org `** Device packs`. MODIFIED README.org `** Command-line use` limits: points to device packs.

** Gotchas
- An .atpack contains package.content; packs that the installer bundles do not.
- `RLM_LICENSE` pointed at an empty directory does not give Free mode (see `2026-xclm-license.org`), so the licence probe here has no in-place negative control. The xc16 store path is the same as before the change.

** Risks
- A pack can need another pack (for example a DFP and a tool pack for programming). The IDE reports a missing dependency; `packs` does not resolve dependencies.

* Implementation
- `pkgs/fetch-mplab-pack/default.nix`: URL https://packs.download.microchip.com/<vendor>.<name>.<version>.atpack; `passthru.mplabPackPath` gives <vendor>/<name>/<version>.
- `pkgs/mplab-x-unwrapped/common.nix` `installPhase`: moves packs/* to `$packs`, index.idx to `$out/share/mplab-x/packs/`, and replaces packs with a symlink to /opt/microchip/mplabx/v<version>/packs.
- `pkgs/mplab-x/default.nix` `rootfs`: /opt/microchip/mplabx/v<version> is a real directory with symlinks to the installation's entries except packs and sys; `addPack` copies each pack as symlinks; sys is a symlink copy with the java wrapper.
- The packs folder of the 6.35 installer has 147 packs (146 Microchip, 1 arm), each at <vendor>/<name>/<version> with one version, and index.idx (15 MB), which is the online pack index, not a list of the installed packs.
- index.idx is not a pack, so it is in `out` and every packs folder links it.

* Intent
An exported `mkCiImage` builds a Docker image from an `xc-cli` selection, for CI runners whose seccomp profile blocks unprivileged user namespaces. In the image, the commands of the devshell (`xc16-gcc`, `xc-make`, `xc-run`, `mplab-gen`) run unchanged without bwrap, and produce the same output.

* Summary
*Level:* production · *Tests:* smoke · *Docs:* README

** Scope
*** In scope
- `mkCiImage { xc-cli; extraPackages ? [ ]; name ? "xc-cli"; tag ? null; }`, exported in `legacyPackages` and the overlay like `fetchMplabPack`.
- `mplab-gen` in the image for `xc-cli` with `withMplabProjects = true`: a `run.sh` path for real IDE directories, and real copies of the IDE entries that `mplab-gen-run` binds.
- A stub `mount` that lists no mount points, first on `PATH` in every bwrap environment (`run.sh`) and in the image.
- README.org (helper, image size, seccomp reason) and doc/environment.org (Limits: seccomp, image environment).
*** Out of scope
- An `mplab-x` (IDE) image.
- A non-root container user.
- A binary cache or image registry publishing.
- The GitLab and GitHub CI example tasks (0c9e2e15, 54183995); they can use the helper later.
- Changes to the bwrap environment other than the `mount` stub on `PATH` and the generator-runner check.

** Decisions
- The image root is the `xc-cli` root filesystem, plus `dockerTools.fakeNss`, `/tmp` (mode 1777) and `/root` :: one root filesystem for bwrap and the image keeps them in step. `fakeNss` gives Java a `user.home` for the pack library; the root filesystem has no `/etc/passwd`, `/tmp` or `/root` (measured on an existing `xc-cli` root filesystem).
- `xc-cli` and `extraPackages` are on `PATH` through a `buildEnv`, not merged into the image root :: the root filesystem's `/bin` is a symlink to `/usr/bin`, so a merged package `bin` collides with it.
- The image sets `MPLAB_X_ENV=<rootfs>`, `LD_LIBRARY_PATH=/lib32` and `HOME=/root` :: `run.sh` runs a wrapper directly when `MPLAB_X_ENV` contains its identity, so it does not set `LD_LIBRARY_PATH` itself in the image.
- The image layer replaces each IDE entry that `mplab-gen-run` binds (all top-level subset entries except `packs` and `sys`) with a dereferenced copy :: the generator derives its IDE path from the real path of its jar (design/log/2026-headless-mplab-build.org); in the `xc-cli` root filesystem, `mplab_platform` is a symlink into the store. `packs` and `sys` are already real directories, as in the bwrap binds.
  Rejected:
  - Real copies in the root filesystem: bwrap shows root filesystem entries as symlinks into the store, so the generator still needs its binds; the copy would add about 400 MB to every `xc-cli` closure.
  - Rewriting store paths in the generated makefiles: rejected already in design/log/2026-headless-mplab-build.org (two mechanisms for one problem).
- Inside an environment, the generator runner runs its command directly only when `MPLAB_X_ENV` contains its identity and each bind target resolves to itself (`cd -P` then `pwd -P`) :: the check uses the property that the binds supply, so the `xc-cli` and `mplab-x` bwrap environments keep their refusal.
  Rejected:
  - A separate identity or flag variable for the image: it asserts real paths without checking them.
- `xc-cli.passthru` gains `generatorBindList` (null without `withMplabProjects`) and `mountStub` from `rootfs.nix` :: the image copies exactly the entries that the bwrap generator runner binds, with no second copy of that selection logic.
- A stub `mount` (`rootfs.nix` `mountStub`, exits 0 with no output) is first on `PATH` in each bwrap environment and in the image (user decision, 2026-10-23) :: xclm runs `mount` on each licence check to list mount points; the licence has `hostid=ANY`, so it needs none. The stub removes the `mount: command not found` noise in environments without a host `mount`, and costs about 3.5 ms per compile. Where a host `mount` was visible, compiles were 349 ms (median) with it and 51 ms with the stub on this host.
  Rejected:
  - util-linux in the root filesystem: about 104 ms more per compile where no host `mount` is on `PATH` (Nix build sandbox, image).
  - Keep the message: CI logs need a filter or documentation.
  - Stub at `/usr/bin/mount` in the root filesystem: on NixOS the host `mount` comes first on `PATH`, so behaviour differs between hosts.
  - Stub in the image only: Nix sandbox builds keep the message.

** Shipped
- `mkCiImage { xc-cli; extraPackages ? [ ]; name ? "xc-cli"; tag ? null; }` (`pkgs/mk-ci-image/default.nix`), in `legacyPackages` and the overlay. With xc16 1.61, one DFP and `withMplabProjects = true`, the image is 3.25 GB.
- `mplab-gen` runs in the image: the image has real copies of the generator bind entries, and the generator runner runs directly where each bind target is a real path.
- A stub `mount` first on `PATH` in every bwrap environment and in the image: no `mount: command not found` noise, and faster licensed compiles where a host `mount` is visible (349 ms to 51 ms median for xc16 1.61 on the test host).
- `xc-cli.passthru` gains `generatorBindList` and `mountStub`.

** Gotchas
- On a NixOS host, the bwrap environment finds the host `mount` through `/run/current-system/sw/bin` on `PATH`, so the `mount: command not found` message appears only in the Nix build sandbox and in containers. Probe with `env -i PATH=/usr/bin:/bin` to reproduce it.
- The `.generated_files/flags` hashes in `Makefile-<conf>.mk` depend on the project path, so makefiles that `mplab-gen` writes at different paths differ; the hex does not.

** Risks
- A command run in the environment that calls `mount` (e.g. a build script, or an MPLAB-X tool that looks for a mounted programmer drive) sees no mount points. doc/environment.org documents this.
- A licence bound to a removable-media hostid would not be found. The shipped licence has `hostid=ANY`.
- Only a root container user is tested. A runner that sets a non-root user can fail.

** Follow-ups
- The GitLab and GitHub CI example tasks (0c9e2e15, 54183995) can use `mkCiImage` instead of a runner with unprivileged user namespaces.

* Implementation
- `pkgs/mplab-x/rootfs.nix`: `mountStub` is `writeShellScriptBin "mount" "exit 0"`; the builder returns it and `generatorBindList`. `run.sh` prepends `$mountStubBin` to `PATH` only where it starts bwrap; a nested call inherits the outer `PATH`.
- `pkgs/mplab-x/run.sh`: inside an environment, a generator runner reads its bind list and refuses unless each target is not a symlink, exists, and has a parent that `cd -P` resolves to itself. It then applies the existing identity check.
- `pkgs/mk-ci-image/default.nix`: `contents = [ xc-cli.rootfs dockerTools.fakeNss ]`. `streamLayeredImage` merges contents with `symlinkJoin` (`lndir`), which keeps each root filesystem symlink as a symlink, so `extraCommands` removes each generator bind target and copies its source with `cp -rL`. `PATH` is the stub, a `buildEnv` of `xc-cli` and `extraPackages`, then `/usr/bin:/usr/sbin`.
- The command-line subset is in the image twice: the root filesystem symlinks keep its store path in the closure, and the layer has the 274 MB copy of `mplab_platform`.

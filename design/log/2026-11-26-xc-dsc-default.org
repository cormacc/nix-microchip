* Intent
Firmware work uses XC-DSC from now on. Make the current XC-DSC release (=xc-dsc_4_00=) the compiler of the MPLAB example, its CI image, the documentation examples and the regression-test levels, so that what the repository shows and tests is what its users build with. Keep every XC16 package for reproducible legacy builds.

** Decisions
- Convert the one example instead of adding a second :: both the MPLAB-X path and the later CMake path build the same XC-DSC project.
  Rejected:
  - A separate XC-DSC example beside the XC16 one: two examples and two CI images to maintain for a compiler that is no longer the default.
- Keep the device and the DFP :: only the compiler changes. =xc-dsc_4_00= compiled =main.c= at =-O3= and linked it with =-mdfp=.../dsPIC33E-GM-GP-MC-GU-MU_DFP/1.7.401/xc16= on 2026-11-26 (both exit 0).
  Rejected:
  - dsPIC33CK64MP105 with dsPIC33CK-MP_DFP 1.16.521 (the =bb/package_verify.nix= profile): every device and DFP reference in the documentation would change too.
- Replace the licence check in =build.sh= with a compiler-identity check :: =xc-dsc_4_00= enforces no licence and ships no =xclm= (=doc/licence.org=), so =xclm -status= cannot run.
- Regression levels :: basic is =xc-dsc_4_00=. Thorough is =xc-dsc_4_00=, =xc8_4_00=, =xc32_6_00= and the licensed =xc-dsc_3_31=, so that changes to the runtime environment still run one licence probe. =xc16_1_61= is a special release for licence changes.
  Rejected:
  - =xc-dsc_3_31= in the basic level: every routine change would need a second compiler installation, of a release that production does not use.
- Measure again only what the example produces :: the closure-size rows and the compile timing describe the environment, not a default; they stay as dated XC16 results.
  Rejected:
  - Measure everything again: needs =xc-cli= with the default device packs (the =.packs= derivation writes 14.04 GB) and replaces figures that earlier change-records cite.
- This work is separate from the MPLAB CLI task :: it can ship and publish its image alone.

** Risks
- MPLAB-X 6.35 may not accept hand-written =XC-DSC= / =4.00= toolchain values, or =mplab-gen= may not find XC-DSC. The first plan task starts with this check. Fallback: set the toolchain in the IDE once and commit what it writes.
- The image publication needs the maintainer's GHCR token. The image task has an explicit hand-over point; the other tasks do not wait for it.
- The two-version devshell snippet becomes =xc-dsc_4_00= with =xc-dsc_3_31=. If the 3.31 installer is login-only and no local copy exists, that snippet cannot be run; the worker reports it, and the snippet carries a note. Accepted.
- A routine change can break the licence path and stay unnoticed until the next thorough run. Accepted with the level decision.

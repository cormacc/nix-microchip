* Intent
CI and developers generate and build an MPLAB-X project (`nbproject/configurations.xml`) from the command line in an `xc-cli` environment, without the full IDE installation in the closure. Generated makefiles name stable /opt/microchip/... paths, not store paths, whichever environment generates them.

* Summary
*Level:* production · *Tests:* smoke · *Docs:* README

** Scope
*** In scope
- A generator command `mplab-gen` that runs the makefile generator with a real /opt/microchip/mplabx/v<version> directory (bind mount), so that it writes /opt paths; `-Djava.home` in the existing java wrapper for `MP_JAVA_PATH`. In `mplab-x` and in `xc-cli`. Builds and compiler calls run without the bind.
- An IDE command-line subset package built from `mplab-x-unwrapped` by a committed file inventory: java, the makefile generator and its jars, `make`, `hexmate`, `fixDeps`, `extractobjectdependencies.jar` and `dat/en_msgs.txt`. A script that regenerates the inventory for a new IDE version.
- An `xc-cli` argument `withMplabProjects ? false` that adds the subset, and a generator command `mplab-gen <project>@<conf>...` that passes `-compilers=` for each selected compiler.
- README.org: the CI workflow (generate, then build), the effect of `nbproject/private`, and committed versus generated makefiles. AGENTS.md: layout.
*** Out of scope
- Replacing MPLAB makefiles (CMake, or a Makefile that reads configurations.xml).
- The GUI. Programming and debugging tools (`mdb`, `ipecmd`).
- CI runner set-up (unprivileged user namespaces) and a private binary cache.
- Downstream project changes, including the migration of downstream flakes from the removed `mplab-x` `compilers` argument.
- A smaller jar set than the measured inventory.

** Acceptance
*** Core functionality
- [ ] With the IDE bind, the compile cost of the extra mount is measured and recorded (time per compiler call, with and without the bind).
- [ ] In `mplab-x`, `mplab-gen` writes `.mk` files that contain no `/nix/store` string for the downstream xc16 project (both configurations).
- [ ] `mplab-make`, `mplab-x-run` and the compiler wrappers run without the bind: their root filesystem and mounts are unchanged.
- [ ] The subset package contains every jar that the generator manifest's `Class-Path` names; its build fails when one is missing.
- [ ] `xc-cli` with the subset and xc16 1.61 has no `mplab-x-unwrapped` path in its runtime closure.
- [ ] In that `xc-cli`, the generator command writes `.mk` files that are byte-identical to those that `mplab-x` writes for the same project and private state.
- [ ] In that `xc-cli`, `xc-make` builds both configurations of the downstream xc16 project, and each hex file is byte-identical to the `mplab-x` build.
- [ ] The `-O3` compiles of that build print no Free-mode diagnostic, and `xclm -status` shows `Mode: PRO`.
- [ ] A Nix derivation generates and builds one configuration in the Nix build sandbox.
- [ ] README.org documents the generator command, the CI workflow and the `xc-cli` argument.
*** Edge cases
- [ ] `xc-cli` without the argument is unchanged: same root filesystem file list, no bind.
- [ ] The generator command with no selected compiler fails with a message.
- [ ] Generation does not read toolchains from `nbproject/private` or `PATH` when the command passes `-compilers=`.
*** Anti-criteria
- [ ] Must not: modify payload executables or jars.
- [ ] Must not: add a mount to builds or compiler calls. Only `mplab-gen` runs have the IDE bind.
- [ ] Must not: change the root filesystem of `xc-cli` or `mplab-x` beyond the bind, the /opt directory chain and the java wrapper.

** Decisions
- A bind mount gives the IDE files a real /opt/microchip/mplabx/v<version> path in `mplab-gen` runs only (user decisions, 2026-10-22) :: the generator derives its IDE path from the canonical location of its own jar (`AbstractContext.determine`, `ReleaseContext`) and overwrites `netbeans.home`, so a symlink into the store gives store paths. The bind adds 72.6 ms to each compiler call (median of 35 xc16 1.61 `-O3` compiles: 114.6 ms without, 187.1 ms with), so builds run without it; the generated makefiles reach `make` and `hexmate` at /opt through the existing symlinks. CI can also keep its own generated makefiles and not run `mplab-gen`.
  Rejected:
  - The bind in every environment: 72.6 ms more for each compiler call; it would also give stable paths in makefiles that the GUI writes, which matters only for projects that commit makefiles written by the GUI.
  - Rewrite the store prefix in the generated files: no mount, but makefiles that the GUI writes keep store paths.
  - Bind in `mplab-x` and rewrite in `xc-cli`: two mechanisms for one problem.
  - A real directory for each IDE entry in bwrap arguments: the IDE has more entries than bwrap's 9,000-argument limit.
- The subset is a committed file inventory, with a guard for the generator manifest :: the manifest `Class-Path` names 275 jars; the generator also loads 32 jars that it does not name (JRE jars, the generator jar, tool jars such as `ICD4X.jar`).
  Rejected:
  - Manifest `Class-Path` only: misses those 32 jars.
  - Whole directories of `mplab_platform`: not measured; larger.
- The generator command passes `-compilers=/opt/microchip/<pname>/v<version>/bin` for each selected compiler :: without it, the generator found a compiler wrapper through the project's private settings and wrote its store path to `MP_CC` and related variables.

** Risks
- The inventory covers the generator and the build of one xc16 project. Other project types, compilers and error paths can need other files.
- `nbproject/private` changes the generated output (e.g. the dependency footer). A comparison needs the same private state.
- Makefiles that the GUI writes during a GUI build contain store paths. A project that commits its makefiles regenerates them with `mplab-gen` first.
- The subset still needs the installer at build time: a cold build without a binary cache runs the 16 GB installer.

** Follow-ups

* Context
Measured 2026-10-22 on a downstream xc16 project (two configurations, XC16 1.61, dsPIC33E-GM-GP-MC-GU-MU_DFP 1.7.401) with a prototype:
- Store paths in generated makefiles: `PATH_TO_IDE_BIN`, `PATH`, `MP_JAVA_PATH`, `DEP_GEN`, and the hexmate post-build recipe (`hexmate` and `--edf=.../dat/en_msgs.txt`). `DFP_DIR` was already /opt.
- With the bind and `-Djava.home`, the generated `.mk` files had no store path. The subset (355 files, 397 MB) generated byte-identical `.mk` files, and the build produced byte-identical hex files for both configurations.
- Closures: `xc-cli` with xc16 1.61 and the DFP 2.40 GiB; with the subset 2.77 GiB; the full `mplab-x` override 5.49 GiB.
- At build time the makefiles ran only `make` (needs `libdl`, `libc`) and `hexmate` (static) from the IDE; `fixDeps`, `extractobjectdependencies.jar` and `en_msgs.txt` were not read.

* Intent
A user who selects only compilers gets the device packs for their architectures, and the IDE gets the programmer and debugger tool packs and IPE, without lists of packs in this repository. Small commands show the installer options, the available packs and the `xc-cli` configuration that an MPLAB project needs.

* Summary
*Level:* production · *Tests:* smoke · *Docs:* README

** Terms
- Device packs (DFPs): device support for compilers and the IDE, selected by the installer options `--8bitmcu`, `--16bitmcu`, `--32bitmcu` and `--othermcu`.
- Tool packs (`*_TP`): programmer and debugger support, marked in the bundled `index.idx` with `atmel:tool-name`. Every installer run installs them, whatever the MCU options.

** Scope
*** In scope
- A derivation function that runs the installer with selected MCU options and keeps only device packs, and a derivation that keeps only tool packs; both classify packs by `atmel:tool-name`.
- `xc-cli` `packs ? null`: `null` selects the device packs of the MCU options for the selected compilers (xc8: `--8bitmcu`; xc16 and xc-dsc: `--16bitmcu`; xc32: `--32bitmcu`) plus `--othermcu`; a list selects exactly those packs.
- `mplab-x` `toolPacks ? null`: `null` selects all bundled tool packs; a list of tool-pack names (e.g. `[ "PICkit5_TP" ]`) selects only those; `[ ]` selects none. `packs ? [ ]` keeps its current meaning (extra packs, e.g. a newer tool pack from `fetchMplabPack`). `mplab_ipe` and `ipecmd` in `mplab-x`.
- Babashka tasks in a new `bb.edn`: `bb installer-help` (installer `--help` and `--version`); `bb packs` (pack names, versions and kinds, bundled with the packaged IDE or from Microchip's online index); `bb project-config <project>` (an `xc-cli` configuration block from an MPLAB project's `nbproject/configurations.xml`).
- `devShells.x86_64-linux.default` in `flake.nix`, with `babashka`.
- `doc/packaging.org`, linked from README.org: the packaging options of `xc-cli` and `mplab-x` (compilers, device packs, tool packs, `withMplabProjects`, `fetchMplabPack`), the Babashka tasks, and a table of closure sizes. AGENTS.md: layout.
*** Out of scope
- Bundled pack lists for MPLAB-X versions other than the packaged one (only the latest IDE is retained); other versions come from Microchip's online index and each pack's `.pdsc` release list.
- A standalone IPE package.
- Selection of single bundled device packs by name (use `fetchMplabPack`).
- Changes to `fetchMplabPack`, compiler packages or the root filesystem builder.

** Decisions
- Packs come from installer runs with Microchip's MCU options; tool packs are told apart by `atmel:tool-name` in the bundled `index.idx` (measured 2026-10-23, 6.35: the four options install disjoint sets of 25, 22, 82 and 2 packs; every run adds the same 16, which are the 15 tool packs and `arm/CMSIS`; the sets and the 16 add up to the full 147) :: no pack list in this repository; a new MPLAB-X version brings its own sets.
  Rejected:
  - Rules from each pack's compiler directory: 37 of the 82 32-bit packs have no `xc*` directory.
  - Lists of pack names: per-release maintenance.
- One installer run for each combination of MCU options :: `arm/CMSIS` comes with every run, so separate derivations for each option would give duplicate packs when combined (the root filesystem rejects them).
  Rejected:
  - One derivation for each option, combined in the root filesystem: needs a special case for `arm/CMSIS`.
- `null` default, explicit list replaces it :: a simple install needs no pack configuration; a pinned configuration gets exactly its packs, and the default and explicit packs cannot collide. `--othermcu` (4 MB) comes only with the default.
- `mplab-x` `toolPacks` takes Microchip's tool-pack names; a selection copies the named packs from the derivation with all tool packs :: the names come from the installer's index, so no list is kept here; one installer run serves every selection.
  Rejected:
  - One installer run for each selection: about 2 minutes each, for a copy of a few directories.
  - Overloading `mplab-x` `packs`: `packs` already adds extra packs.
- `mplab-x` gets the tool packs and IPE; no standalone IPE package :: `--ide 0` keeps 1.45 GB of `mplab_platform` and all of Java (measured 2026-10-23: 4.7 GB `/opt` with all MCU options off, against 4.9 GB with the IDE).
- The commands are Babashka tasks in `bb.edn`, with `babashka` in the flake's devshell (user decision, 2026-10-23) :: they run on the host from a checkout of this repository, and the project task needs `nix` to compute pack hashes.
  Rejected:
  - Flake apps: the user chose Babashka tasks.
- Packaging options in a supporting document, `doc/packaging.org`, linked from README.org (user allowed either) :: README.org already has more than 500 lines.

** Risks
- BREAKING: `xc-cli` with compilers and no `packs` grows by the device packs of its architectures (about 2.9 GB for 8-bit, 3.0 GB for 16-bit, 5.2 GB for 32-bit); default `mplab-x` grows by the tool packs (2.89 GB: about 355 MB for each of the eight PICkit, ICD, ICE, Snap and PKOB packs).
- Each new combination of MCU options runs the installer once more (about 2 minutes, a build directory of up to 18 GB).
- A future installer can change the MCU options or `atmel:tool-name`; the derivations fail when a selected option gives no device pack or the tool-pack set is empty.
- The project command's pack hash depends on `fetchMplabPack` (fetchzip, manifest removed); it computes the hash through `fetchMplabPack` itself, not by a separate unpack.

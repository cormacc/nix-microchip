* Intent
Microchip recommends that users move from MPLAB-X to MPLAB for VS Code, and names the Node.js MPLAB CLI (npm =@mplab/cli=, alpha) for CI. Let a firmware project build in the Nix sandbox and in CI from committed CMake files, with a closure that has no MPLAB-X installer run. The =mplab= package is the means to make those files, not the goal. The MPLAB-X path stays.

** Decisions
- The CLI is a generator; nixpkgs =cmake= and =ninja= build :: Microchip's remote app manifest (the "shelf") sets =allowPathDetection: false= for =ninja=, =make= and the XC compilers, so =mplab project build= ignores tools on =PATH=. =project build -g= writes correct files and exits 2; the script checks the files, not the status.
- Thin package, example script, committed files :: the package has no npm dependencies (="dependencies": {}=), so it is an unpacked tarball with a =nodejs_22= wrapper.
  Rejected:
  - A reusable =mplab-cmake-gen= command in =xc-cli=: a public interface on the false exit status and file layout of an alpha tool.
  - Generation inside the Nix build: it needs the network (shelf, pack download), and the generated target name has a suffix that prevents a fixed output hash.
- Generated files live in =examples/mplab/firmware.X=, beside =nbproject/= :: one source tree serves both paths and shows a migration.
  Rejected:
  - A separate =examples/mplab-cmake/=: duplicate source.
- The path is a compile-check and simulator-test path :: CLI 0.9.6 passes the constant build type =debug= at both CMake call sites (=dist/main.js=), so the rules have =-D__DEBUG=, =-O0= and =--defsym=__MPLAB_DEBUG=1=. The generator library inside the CLI has a =production= build type that no command-line option selects.
  Rejected:
  - Removing the debug flags from the generated =rule.cmake=: depends on the internal layout of files marked "do not modify", and nobody has shown that it gives the production options.
- The build sets =-DPACK_REPO_PATH= to the pinned packs; generation uses the CLI's own pack copy in a fixed folder under =/tmp= :: with =--pack-folder= at the read-only =/opt/microchip/mplabx/v6.35/packs=, the CLI reports "No devices found when parsing available packs" and fails. The fixed folder makes the committed =PACK_REPO_PATH= default the same on every machine.
- =.generated/cmake-hash.json= is not committed :: it holds the checkout path (=workspacePath=).
- No licence criterion :: =xc-dsc_4_00= enforces no licence.
- XC-DSC only :: the repository standardises on XC-DSC ([[task:b374c23a-4fb0-46ae-8252-dbf2f0433f5c][XC-DSC task]]); XC8 and XC32 generation is not tested.

** Risks
- The CLI is alpha. Its README lists known issues: XC16 per-file options missing on Linux, DFP =-mdfp= options sometimes not passed, intermittent pack download failures.
- Generation reads the shelf and the pack index from Microchip servers. A server change can break generation with the same pinned CLI. Accepted: the committed files still build.
- The DFP copy that the CLI downloads is not covered by a Nix hash. Accepted: the build uses the pinned pack, and the diff of the generated files is reviewed at commit.
- The generated target name has a suffix (=firmware_default_image_cNCS0vI6=). If it changes on each run, the edge criterion fails; the worker reports it and the owner decides.
- The project has two descriptions, =nbproject/= and =.mplab.json= with =cmake/=. They drift unless the script runs after each =nbproject/= change.

#+begin_src sh
#!/usr/bin/env bash
set -euo pipefail
cd -- "$(dirname -- "$0")/firmware.X"
# Fixed folders: the CLI writes the pack folder into rule.cmake as the PACK_REPO_PATH default.
opts=(--pack-folder /tmp/mplab-cli/packs --app-folder /tmp/mplab-cli/apps)
xc-run mplab project import . --force "${opts[@]}"
xc-run mplab packs install --project .vscode/firmware.mplab.json "${opts[@]}"
# The CLI writes the CMake files, then exits 2 because it does not accept cmake and ninja from PATH.
xc-run mplab project build .vscode/firmware.mplab.json --configuration default -g \
  --toolchain /opt/microchip/xc-dsc/v4.00 "${opts[@]}" || true
for f in CMakeLists.txt CMakePresets.json .generated/toolchain.cmake .generated/rule.cmake \
         .generated/main.cmake .generated/file.cmake; do
  test -s "cmake/firmware/default/$f" || { echo "Not generated: $f" >&2; exit 1; }
done

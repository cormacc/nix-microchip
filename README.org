* Overview
This provides Nix packages for Microchip PIC24/dsPIC33 development. =xc-cli= runs selected compilers without the MPLAB-X IDE, and =mplab-x= provides the IDE with its selected compiler. It should be readily adaptable to provide similar packages for XC8 and/or XC32.

The packages included here are primarily the work of https://github.com/nyadiia, in a merge request raised against nixpkgs here:
[[https://github.com/NixOS/nixpkgs/pull/301317]]

I've refactored them a bit and packaged as a flake for instant gratification.

Currently this provides packages for the following, to meet my own immediate needs:
- xc16 v1.21
- xc16 v1.61
- xc16 v2.10
- xc8 v2.50
- xc8 v3.10
- xc8 v4.00
- xc32 v5.10
- xc32 v5.19
- xc32 v6.00
- xc-dsc v3.31
- xc-dsc v4.00
- mplab-x v6.35 (=mplab-x-unwrapped=)

Only the latest verified MPLAB-X version is retained. Legacy compiler versions are retained for reproducible firmware builds; compiler-version requirements do not require us to retain older IDE packages.

Adding additional versions is trivial -- see instructions in the section [[Adding packages]].

Pull requests adding additional packages and/or addressing any of the [[./TASKS.org][project tasks]] (or others I haven't considered) welcome.

* Usage

The Microchip compilers and MPLAB-X are dynamically linked binaries, so they need an FHS environment on NixOS.
The compiler packages are unwrapped. =xc-cli= wraps selected compilers in an FHS environment without the IDE. =mplab-x= wraps the IDE and compiler(s) in its FHS environment. I have not tested Microchip programmers because my development flow does not need them (hex image programming via a bootloader and debugging via log trace rather than ICD).

Here's a sample flake illustrating use from a microchip project. This installs MPLAB-X and XC16 in a bubble-wrapped environment.
... (this overlay is hard-coded to x86_64-linux for now, so the forEachSupportedSystem stuff is aspirational )...

N.B. I'm using nixpkgs-unstable, as that's what I'm tracking for NixOS on my dev machines. Because of the wrapping you'll want to use a nixpkgs version with the same(?ish?) version of libc as your OS -- otherwise this'll fail to run. I.e. you may need to pass a different nixpkgs via inherit for compatibility with your own OS.

#+begin_src nix
  {
    description = "A Nix-flake-based ceedling (c+ruby) environment";
    #N.B. microchip compiler not nixpkg-ed, so assuming installed via system package manager
    #N.B. ruby dependencies controlled via Gemfile, bundler and bundix pfte

    inputs = {
      nixpkgs.url = "github:NixOS/nixpkgs/nixpkgs-unstable";
      microchip.url = "github:cormacc/nix-microchip";
    };

    outputs = { self, nixpkgs, microchip }:
      let
        supportedSystems = [ "x86_64-linux" "aarch64-linux" "x86_64-darwin" "aarch64-darwin" ];
        forEachSupportedSystem = f: nixpkgs.lib.genAttrs supportedSystems (system: f {
          pkgs = import nixpkgs {
            inherit system;
            config.allowUnfree = true;
            overlays = [
              microchip.overlays.default
            ];
          };
        });
      in
      {
        devShells = forEachSupportedSystem ({ pkgs }: {
          default = pkgs.mkShell {
              buildInputs = with pkgs; [
                mplab-x #build dependencies - incorporates xc16 v1.61
                cmake clang-tools #editor support (emacs/lsp)
              ];
            };
        });
      };
  }
#+end_src

** Command-line use

Use =xc-cli= for a compiler-only environment. It has no default compilers or packs, so select both with its =compilers= and =packs= arguments. It supplies =xc-run <command> [args...]=, =xc-make [args...]= and a wrapper for each executable of the first selected compiler of each family. =xc-make= runs GNU Make in the environment, forwards its arguments and preserves its exit status.

#+begin_src nix
packages = [
  (pkgs.xc-cli.override {
    compilers = with pkgs; [ xc16_1_61 xc16_2_10 ];
    packs = [
      (pkgs.fetchMplabPack {
        name = "dsPIC33E-GM-GP-MC-GU-MU_DFP";
        version = "1.5.258";
        hash = "sha256-GdndiTwmMizusNoGvP3TleTiD9E5LidbJoUEEjS0se0=";
      })
    ];
  })
];
#+end_src

With this environment, =xc16-gcc= runs v1.61 and =xc-run /opt/microchip/xc16/v2.10/bin/xc16-gcc= runs v2.10. The selected DFP is at =/opt/microchip/mplabx/v6.35/packs/Microchip/dsPIC33E-GM-GP-MC-GU-MU_DFP/1.5.258/xc16= for =-mdfp=.

The =mplab-x= package also supplies these commands:
- =mplab-x-run <command> [args...]= runs a command inside the MPLAB-X environment. In this environment, each compiler is at =/opt/microchip/<compiler>/v<version>=, where MPLAB-X expects it.
- =mplab-make [args...]= runs the packaged GNU Make inside the MPLAB-X environment. It forwards arguments and preserves the exit status; ordinary =make= is unchanged.
- One wrapper for each executable of the default compiler, e.g. =xc16-gcc=, =xc16-bin2hex= and =xclm=. Each wrapper runs its executable through =mplab-x-run=.

The compilers must run unmodified in this environment. A compiler that is patched to run directly on NixOS (=autoPatchelfHook=) detects the change and runs in Free mode. See [[#compiler-licence-pro-optimisations][Compiler licence (PRO optimisations)]].

Use the =compilers= argument to select the compilers. Two or more versions of one compiler can coexist. The first compiler of each family in the list is the default on the command line:

#+begin_src nix
  packages = [
    (pkgs.mplab-x.override { compilers = with pkgs; [ xc16_1_61 xc16_2_10 ]; })
  ];
#+end_src

With this devshell, MPLAB-X can use both versions, =xc16-gcc= runs v1.61, and =mplab-x-run /opt/microchip/xc16/v2.10/bin/xc16-gcc= runs v2.10.

MPLAB-X registers each =PATH= directory that contains a compiler as a toolchain. =mplab_ide= removes each directory that contains =mplab-x-run= from =PATH= before it starts the IDE, so the IDE registers only the compilers in =/opt/microchip=. A toolchain that an earlier =mplab-x= build registered (a =/nix/store/...-mplab-x/bin= directory) stays in the IDE's build tool list until you remove it there.

When =compilers= is not set, the =xc8=, =xc16=, =xc32= and =xc-dsc= arguments supply the list, so an override such as =mplab-x.override { xc16 = pkgs.xc16_2_10; }= continues to work. When =compilers= is set, the package ignores these arguments.

Use =mplab-make= for MPLAB-generated makefiles. Their local settings prepend the IDE's unwrapped =bin= directory to =PATH=, so a recursive =make= or another bundled tool can fail on NixOS outside the environment, even when the compiler commands are wrapped. For example, from a project's firmware directory:

#+begin_src sh
mplab-make -j8 -f Makefile CONF=bootloadable
#+end_src

Each call from outside the environment sets up the environment again. With xc16 1.61, a wrapped =-O3= compile of a small file took approximately 0.2 s, and =mplab-x-run true= took approximately 0.03 s (measured 2026-10-21). For a build that calls the compiler many times, run the whole build in one environment with =mplab-make=, or use =mplab-x-run ./build.sh= for a build script. Inside the environment, the wrappers run the compiler directly; ten compiles took 1.8 s in total, including the set-up.

The environment shows these host directories, writable: =/dev=, =/home=, =/nix=, =/proc=, =/run=, =/sys=, =/tmp=, =/var= and the working directory. Other top-level host directories (e.g. =/boot=, =/mnt= and =/srv=) are not visible, so a build cannot use an absolute path in them. =/etc=, =/usr= and =/opt= merge the MPLAB-X root filesystem with the host, and the root filesystem has precedence. The root filesystem is read-only. Do not add mounts to the environment without a measurement: on each call, =xclm= searches each block-device mount for licence files, so each mount makes each compile slower (approximately 16 ms on the test host).

The environment includes 32-bit glibc and libstdc++, for XC16 before 1.50 (32-bit) and for =sim30= (32-bit in every XC16 version).

Limits:
- The environment needs unprivileged user namespaces. It does not need FUSE. In a test derivation in the Nix build sandbox on NixOS, =mplab-x-run= compiled and linked with xc16 1.61 and 1.21, =xc16-bin2hex= made a hex file, and =xclm -status= reported PRO mode (measured 2026-10-21).
- The licensed compilers print =Error getting handle for device N: Access denied (insufficient permissions)= on stderr for each USB device that the user cannot open. Microchip's udev rules do not remove all of these messages. The exit status is not affected. See [[#udev-rules][Udev rules]].
- XC8 3.10 and later, XC32 and XC-DSC 3.31 and 4.00 need a device pack (=-mdfp=). See [[#device-packs][Device packs]].

** Device packs

A device family pack (DFP) gives the compilers the device headers, linker scripts and device data. MPLAB-generated makefiles pass =-mdfp= to each compile, link and =xc16-bin2hex= step. XC8 3.10 and later, XC32 and XC-DSC 4.00 need =-mdfp= for all devices. A tool pack (TP) gives MPLAB-X the support for a programmer or debugger.

The =mplab-x= environment has one packs folder, =/opt/microchip/mplabx/v<version>/packs=. The IDE and the MPLAB-X command-line scripts (e.g. =prjMakefilesGenerator.sh=) use it, and the makefiles that they generate set =DFP_DIR= to a pack in it, e.g. =/opt/microchip/mplabx/v6.35/packs/Microchip/dsPIC33E-GM-GP-MC-GU-MU_DFP/1.5.258=. Packs that the IDE downloads go to =~/.mchp_packs=, as on other Linux installations.

By default, the packs folder contains all the packs that the MPLAB-X installer bundles: 147 packs, 14 GB for 6.35. The =mplab-x-unwrapped= package keeps them in its =packs= output, so its main output does not include them. Use the =packs= argument of =mplab-x= to select packs, and =fetchMplabPack= to pin a pack from Microchip's pack repository:

#+begin_src nix
  packages = [
    (pkgs.mplab-x.override {
      packs = [
        (pkgs.fetchMplabPack {
          name = "dsPIC33E-GM-GP-MC-GU-MU_DFP";
          version = "1.5.258";
          hash = "sha256-GdndiTwmMizusNoGvP3TleTiD9E5LidbJoUEEjS0se0=";
        })
      ];
    })
  ];
#+end_src

With this selection and xc16 1.61, the =mplab-x= closure was 5.9 GB; with the bundled packs, it was 19.7 GB (measured 2026-10-21). Pin the pack version that the project's =nbproject/configurations.xml= names in its =<pack>= element. The bundled packs change with the IDE version: MPLAB-X 6.35 bundles dsPIC33E-GM-GP-MC-GU-MU_DFP 1.7.401, not 1.5.258.

=fetchMplabPack= takes =name=, =version=, =hash= and =vendor= (default ="Microchip"=). It downloads =https://packs.download.microchip.com/<vendor>.<name>.<version>.atpack=. Its output is the pack root, so a derivation can use the pack directly, e.g. =-mdfp=${pack}/xc16=. The output does not include the archive manifest =package.content=, so its hash is the =nix hash path= of an installed copy of the same pack version. To get the hash, either:
- run =nix hash path= on the pack in the bundled packs, e.g. =$(nix build '.#mplab-x-unwrapped.packs' --print-out-paths)/Microchip/<name>/<version>=; or
- set =hash = lib.fakeHash;=, build, and copy the hash from the error message.

The flake exports =fetchMplabPack= in =legacyPackages= and in the overlay. It is a function, so it is not in =packages=.

To add the bundled packs to a selection, put =pkgs.mplab-x-unwrapped.packs= in the list. Two packs at the same =<vendor>/<name>/<version>= make the build fail.

The bundled packs contain approximately 2.5 GB of duplicate files, most of them in the debugger tool packs (measured with =jdupes=, 2026-10-21). Nix does not de-duplicate store files by default. =nix store optimise=, or =nix.settings.auto-optimise-store = true;= on NixOS, replaces duplicate files with hard links. This does not make a download from a binary cache smaller.

** Udev rules

Two types of USB access are related to udev rules:

- Hardware tools :: MPLAB-X uses a programmer or debugger (PICkit, ICD, SNAP etc.) only if the user can open its USB device. The =mplab-x-unwrapped= package ships Microchip's udev rules in =lib/udev/rules.d=. They give world read/write access (=MODE="666"=) to Microchip, Atmel and J-Link USB devices, so no group membership is necessary.
- Licence dongle scan :: The licence manager of the licensed compilers (=xclm=) opens every USB device on the bus to look for a licence dongle. For each device that the user cannot open, it prints a message on stderr, in the MPLAB-X build console and on the command line.

#+begin_example
Error getting handle for device 0: Access denied (insufficient permissions)
#+end_example

These messages do not change the exit status and do not stop a build. Microchip's rules do not remove them, because the rules apply only to Microchip, Atmel and J-Link devices. On a test host with 28 USB devices and Microchip's rules installed, one xc16 1.61 compile printed 26 messages. The user had write access to the other 2 devices: one by a =MODE="666"= rule and one by a =uaccess= ACL (measured 2026-10-21). xc16 1.61's =xclm= does not accept the =<xclm:Dongle xclm:enabled="false" />= element from xc8 3.10's =xclm.conf=. It prints =Unrecognized value in xclm config file: xclm:Dongle= and continues the scan.

To remove the messages, also give the user access to all USB devices with the =uaccess= tag. systemd-logind then gives the user of the active local session an ACL on each USB device. A user without an active local session (e.g. a CI runner) still gets the messages. Do not add this rule if local users must not have raw access to all USB devices, such as keyboards and security keys. The =uaccess= tag has an effect only in a rules file that sorts before =73-seat-late.rules=. Thus, on NixOS, =services.udev.extraRules= (which writes =99-local.rules=) is too late.

udev runs on the host, outside the bubblewrap environment, so install the rules at system level. On NixOS:

#+begin_src nix
  # In a NixOS module. The NixOS pkgs set is separate from any Home Manager or
  # devShell pkgs set, so apply the overlay here too:
  nixpkgs.overlays = [ microchip.overlays.default ];
  services.udev.packages = [
    pkgs.mplab-x-unwrapped
    # or, without the overlay:
    # microchip.packages.x86_64-linux.mplab-x-unwrapped

    # Optional: access to all USB devices, which removes the licence dongle scan messages.
    (pkgs.writeTextDir "lib/udev/rules.d/71-usb-uaccess.rules" ''
      SUBSYSTEM=="usb", ENV{DEVTYPE}=="usb_device", TAG+="uaccess"
    '')
  ];
#+end_src

...then rebuild and replug the device (or run =sudo udevadm control --reload-rules && sudo udevadm trigger=).

On other distros, copy the rules into =/etc/udev/rules.d/= instead:

#+begin_src sh
  sudo cp $(nix build .#mplab-x-unwrapped --print-out-paths)/lib/udev/rules.d/* /etc/udev/rules.d/
  # Optional: access to all USB devices, which removes the licence dongle scan messages.
  echo 'SUBSYSTEM=="usb", ENV{DEVTYPE}=="usb_device", TAG+="uaccess"' | sudo tee /etc/udev/rules.d/71-usb-uaccess.rules
  sudo udevadm control --reload-rules && sudo udevadm trigger
#+end_src

** Compiler licence (PRO optimisations)

Microchip states that previously paid MPLAB XC PRO versions are free (https://www.microchip.com/en-us/tools-resources/develop/mplab-xc-compilers), and issues the licence from the "software products" section of myMicrochip (https://www.microchipdirect.com/software-products). Without a licence the compilers run in Free mode, which limits the optimisation levels.

The licence is shipped as the =microchip-xclm-license= package (=pkgs/xclm-license/=). Its =microchip.lic= is the licence block that Microchip's =linux.sh= installer writes into =/opt/microchip/xclm/license/=. It lists seven permanent features with =hostid=ANY=: =swxc8-pro=, =swxc16-pro=, =swxc32-cpp=, =swxc8-fs=, =swxc16-fs=, =swxc32-fs= and =swanaly-ts=. Of these, the packaged compilers use =swxc8-pro= (XC8 2.50 and 3.10), =swxc16-pro= (XC16 1.21, 1.61 and 2.10, and XC-DSC 3.31) and =swxc32-cpp= (XC32 5.10). The file has no XC-DSC feature.

Each XC8, XC16, XC32 5.10 and XC-DSC 3.31 package rewrites the =xclm:path= attribute in its =etc/xclm.conf= to the store path of =microchip-xclm-license=. The compilers then run in PRO mode without any manual licence step, with or without the =mplab-x= wrapper.

Which packaged versions enforce licensing (checked with the probes below):
- xc16 1.61 and xc16 2.10: yes.
- xc16 1.21: yes. =xclm -status= lists the node-locked licences (e.g. =Product:swxc16-pro Version:1.0 Key:swxc16-pro-permanent=) and has no =Mode: PRO= line, so use the =-O3= probe. Without the licence, =-O3= prints =Options have been disabled due to restricted license= and =Visit http://www.microchip.com/ to purchase a new key.=; with it, nothing.
- xc8 2.50 and xc8 3.10: yes.
- xc8 4.00: no. It ships no =xclm= and no =etc/xclm.conf=, so there is nothing to patch, and =-O3= gives no licence diagnostic.
- xc-dsc 3.31: yes, and it uses the =swxc16-pro= feature. The installer needs =--LicenseType FreeMode --netservername localhost=. With only =swxc16-pro= in the licence directory, =-O3= and =-Os= print no diagnostic. With no licence, or with any other single feature of the file, they print =Options have been disabled due to restricted license= and =Visit https://www.microchip.com/compilers to purchase a new key.=. =xclm -status= shows no =xc-dsc= product line, so use the compile probe for this compiler. =-O0= to =-O2= print nothing in either mode.
- xc-dsc 4.00: no. It ships no =xclm= and no =etc/xclm.conf=, and =-O3= and =-Os= give no licence diagnostic. Microchip documents that v4.00 and later need no key.
- xc32 5.10: yes, and it uses the =swxc32-cpp= feature (=swxc32-pro-permanent=). The installer needs =--LicenseType FreeMode --netservername localhost=. =xclm -status= shows =Product: xc32 ... Mode: cpp Key: swxc32-pro-permanent=; the mode is =cpp=, not =PRO=. Without the licence, =-O3= prints =Compiler option (Optimization level > 2) ignored because this feature requires the MPLAB XC32 PRO compiler=, and =-Os= prints the same with =(Optimize for size)=. Each is followed by a note to visit http://www.microchip.com/MPLABXCcompilers. With the licence, they print nothing.
- xc32 5.19 and xc32 6.00: no. Neither installs =xclm= or =etc/xclm.conf=, the installers have no licence options, and the compiler lists its licence options (=-mskip-license-check= and others) as obsolete. =-O3= and =-Os= give no licence diagnostic. No Free-mode build of these versions was available as a negative control. Microchip documents that v6.00 and later need no key, and 5.19 is the XC32 Functional Safety release. The XC32 6.00 release notes list no release between 5.10 and 5.19.

To check that a compiler runs in PRO mode, use either probe. The compilers are dynamically linked, so run them inside the =mplab-x= environment (e.g. with =mplab-x-run= or the command-line wrappers) or an equivalent FHS environment.
- =xclm -status=: for a licensed compiler, the output includes a line for its own product with =Mode: PRO=, for example =Product: xc16 ... Mode: PRO Key: swxc16-pro-permanent=. In Free mode the output has no such line.
- An =-O3= compile: in Free mode, =xc16-gcc= prints =Options have been disabled due to restricted license=. In Free mode, =xc8-cc= (2.50 and 3.10) prints the advisory =(2051) the current license does not permit the selected optimization level, using optimization level 2=. The xc8 advisory does not change the exit status (0), so search the output for =(2051)=. =xc8-cc= 3.10 and 4.00 also need a device pack (=-mdfp=). =xc-dsc-gcc= 3.31 prints the same two lines as =xc16-gcc= for =-O3= and =-Os=, and it needs a DFP for the dsPIC33CK64MP105 probe. =xc32-gcc= 5.10 (which prints the diagnostics quoted above) and =xc-dsc-gcc= 4.00 need a device pack (=-mdfp=) too.

If Microchip reissues or revokes the licence, the compilers can fall back to Free mode and no automatic check reports it, so repeat the probes after an update. To use a reissued licence, replace =pkgs/xclm-license/microchip.lic= with the new file. No other file changes.

Host-level installation of the licence (a =systemd.tmpfiles.rules= symlink to =${microchip-xclm-license}=) for unwrapped use is a possible follow-up that this overlay does not provide.

* Adding packages

** XC16

The xc16 package has been refactored to put most of nyadiia's work into a shared common.nix, and pass the version and installer archive hash in as parameters. So adding a new compiler version just requires creating a new file containing the version number and hash in [[./pkgs/xc16]].

See the example below for xc16 v1.61 (from [[./pkgs/xc16/1.61.nix]]):

#+begin_src nix
import ./common.nix {
  version = "1.61";
  hash = "sha256-Wi0vhJWt+WiNq41daf7e7tJeJmt3/M3t2TJbkJQTNEg=";
}
#+end_src

And then add a new line to [[./pkgs/default.nix]]:

#+begin_src nix
   xc16_1_61 = pkgs.callPackage ./xc16/1.61.nix { inherit microchip-xclm-license; };
#+end_src

XC16 before 1.50 is 32-bit. For these versions, [[./pkgs/xc16/common.nix]] fetches =xc16-v<version>-linux-installer.run.tar= from the DeviceDoc location, installs with 32-bit glibc, and does not give the =--LicenseType= option, which these installers do not have. This is verified for 1.21 only.

Pass =microchip-xclm-license= explicitly: both =packages= and =overlays.default= in [[./flake.nix]] give =pkgs/default.nix= a nixpkgs set without this flake's packages, so =callPackage= cannot find it in =pkgs=. See [[#compiler-licence-pro-optimisations][Compiler licence (PRO optimisations)]].

** MPLAB-X

To upgrade MPLAB-X, add a version/hash file in [[./pkgs/mplab-x-unwrapped/]] and register it in [[./pkgs/default.nix]]. Build and verify the new IDE before changing =mplab-x-unwrapped= to point to it. Once verified, remove the superseded IDE version files and their package attributes. Unlike compilers, only the latest verified IDE is retained.

See the example below for MPLAB-X v6.35 (from [[./pkgs/mplab-x-unwrapped/6.35.nix]]):
#+begin_src nix
import ./common.nix {
  version = "6.35";
  hash = "sha256-THRzY9z7MVcmQ5+WjQ4lsLFyFLubpdL9Sn87qyjFZwU=";
}
#+end_src


The corresponding entries in [[./pkgs/default.nix]] are:

#+begin_src nix
   mplab-x-unwrapped_6_35 = pkgs.callPackage ./mplab-x-unwrapped/6.35.nix { };
   mplab-x-unwrapped = mplab-x-unwrapped_6_35;
#+end_src


** XC8

XC8 is packaged in the same manner as XC16 -- adding a new version just requires a new version/hash file in [[./pkgs/xc8]] and a line in [[./pkgs/default.nix]] that passes ={ inherit microchip-xclm-license; }=, as for XC16.

The =mplab-x= package bundles XC16 only. Use the =mplab-xc8= package for an MPLAB-X wrapped with XC8 instead, or set the =compilers= argument of the mplab-x package to bundle any combination. See [[#command-line-use][Command-line use]].

** XC32, XC-DSC etc.

XC32 ([[./pkgs/xc32]]) and XC-DSC ([[./pkgs/xc-dsc]]) follow the same pattern: a new version/hash file in the package directory and a line in [[./pkgs/default.nix]].

Both lines pass ={ inherit microchip-xclm-license; }=. The package files gate the =xclm.conf= rewrite and the installer licence flags on the version (XC32 below 5.19, XC-DSC below 4.00).

#+begin_src nix
   xc32_6_00 = pkgs.callPackage ./xc32/6.00.nix { inherit microchip-xclm-license; };
   xc-dsc_4_00 = pkgs.callPackage ./xc-dsc/4.00.nix { inherit microchip-xclm-license; };
#+end_src

The =xc32= and =xc-dsc= attributes default to the latest packaged version. =mplab-xc32= and =mplab-xc-dsc= are MPLAB-X wrapped with those compilers. The wrapper links each compiler as =/opt/microchip/xc32/v<version>= or =/opt/microchip/xc-dsc/v<version>=, which is where the installers install by default.

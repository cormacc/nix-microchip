nixpkgs 9397dcb0 (2026-11) marks =gtk2= broken (removal planned before NixOS 27.05, https://github.com/NixOS/nixpkgs/issues/410814). =pkgs/mplab-x/default.nix= takes =gtk2= as an argument and lists it in =fhsTargetPkgs= beside =gtk3=, so any consumer whose =nixpkgs= follows a current nixpkgs fails to evaluate =mplab-x= with "Refusing to evaluate package 'gtk+-2.24.33'". No other package in this repo refers to =gtk2= (at 3cb63fee).

Measured from a downstream flake (2026-11-12): =mplab-x.override { gtk2 = <gtk2 from a nixpkgs imported with config.problems.handlers."gtk+".broken = "warn">; }= evaluates. That flake holds nixpkgs at 5adc5083 until this is fixed.

Acceptance criteria:
- =mplab-x= evaluates against nixpkgs 9397dcb0 or later.
- If =gtk2= is removed: the MPLAB X IDE and MPLAB IPE start and open a project on a display, using GTK3 only.
- If MPLAB X or IPE needs GTK2: the package allows =gtk2= internally, so consumers need no override.

Inline plan:
- Approach: remove =gtk2= from the arguments and =fhsTargetPkgs= of =pkgs/mplab-x/default.nix=. The IDE and IPE run the bundled Zulu 8u452 JRE (=mplab_ide.conf= =jdkhome=); its =libawt_xawt.so= and JavaFX =libglass.so= contain both =libgtk-x11-2.0= and =libgtk-3.so=, and JavaFX ships =libglassgtk3.so=. If a component still needs GTK2, first try a GTK3 JVM option (=-Djdk.gtk.version=3=) in the wrappers; fall back to an internal broken-allowed =gtk2= only if that fails.
- Verify: =nix eval= of =mplab-x= with =--override-input nixpkgs= at 9397dcb0 or later; =nix build '.#mplab-x'=; IDE and IPE start and open =examples/mplab/firmware.X= (Xvfb, then on the user's display), with no =libgtk-x11-2.0= in the process maps; Thorough compiler regression in =mplab-x= (FHS list change); =nix flake check --no-build=.
- Must not: change =flake.lock= or the default versions.
- Must not: patch the bundled JRE or compiler payloads.

Results (2026-11-13):

Without =gtk2=, =mplab-x= and =xc-cli= evaluate. =nix build '.#mplab-x'= and =nix flake check --no-build= pass with the locked nixpkgs. The default =xc-cli= derivation does not change; =xc-cli= with =withMplabProjects= changes through =java-wrapper.nix= (below), and builds.
- Runtime (Xvfb, =LD_DEBUG=libs=, scratch userdir): the IDE loads =libgtk-3.so.0= with and without =gtk2=, and opens =firmware.X=. With =gtk2=, the IPE (JavaFX) loads =libglassgtk2.so=.

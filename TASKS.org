** TODO Provide a compiler-only environment without MPLAB-X
:PROPERTIES:
:CUSTOM_ID: bf4262f4-b2fd-4680-a20e-8d823f6178eb
:CREATED: [2026-10-21 Wed 13:35]
:END:
:LOGBOOK:
- Created [2026-10-21 Wed 13:35]
:END:
The XC compiler packages cannot run directly on NixOS: they are unpatched to keep PRO mode, and xc16-gcc 1.61 run from its store path fails with "Could not start dynamically linked executable" (measured 2026-10-21). Their only runtime environment is mplab-x-run, whose root filesystem includes mplab-x-unwrapped (16.0 GB of a 19.6 GB closure; the xc16 1.61 closure is 1.9 GB). mplab-xc8, mplab-xc16, mplab-xc32 and mplab-xc-dsc in pkgs/default.nix are all mplab-x with a different default compiler. Possible approach: reuse pkgs/mplab-x/run.sh (it needs only root and bwrap) with a small root filesystem: 64-bit and 32-bit glibc, 32-bit libstdc++ for sim30, and the compilers at /opt/microchip/<pname>/v<version>, plus the same CLI wrappers. Not verified: the libraries that xc8, xc32 and xc-dsc need beyond glibc, and whether xclm or the compilers read anything from the IDE installation (e.g. /opt/microchip/mplabcomm). Verify PRO mode for each licensed compiler with the README.org licence probes, including an empty-licence control. MPLAB-generated makefiles put the IDE bin directory on PATH (README.org * Usage ** Command-line use), so they probably still need mplab-x; target user Makefiles, CMake and Nix derivations.
